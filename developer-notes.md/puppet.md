# Introduction to Puppet

Puppet is one of the most established configuration management tools, designed to automate the provisioning, configuration, and management of servers. Unlike Ansible, Puppet is primarily **agent-based** and uses a **declarative language** to define the desired state of a system.

## 1. Core Technology Concepts

### Agent-Based Architecture
In a standard Puppet deployment, a **Puppet Agent** is installed on every target node. This agent periodically communicates with a central **Puppet Server** (formerly known as the Puppet Master). The agent "pulls" the desired configuration (the catalog) from the server and applies it locally. This ensures that nodes automatically correct themselves if their configuration drifts over time.

### Declarative Language
Puppet uses a proprietary Declarative DSL (Domain Specific Language). Instead of writing a script of steps to execute (Imperative), you describe *what* the end state should look like.
- **Imperative (Ansible/Bash)**: "Install package X, then start service Y."
- **Declarative (Puppet)**: "Package X should be present, and service Y should be running."

### Idempotency and Convergence
Like Ansible, Puppet is **idempotent**. However, Puppet focuses on **convergence**. If a system is in an incorrect state, Puppet applies the necessary changes to bring it into the correct state. If the system is already correct, Puppet does nothing.

### Key Components
- **Manifests**: Files ending in `.pp` that contain the Puppet code.
- **Catalog**: A compiled version of the manifests specific to a single node, generated by the Puppet Server.
- **Facter**: A tool that discovers system information (facts) like OS, IP address, and CPU, which Puppet uses to make decisions.
- **Modules**: Reusable collections of manifests, files, and templates.

## 2. Hands-on Example: Deploying an MkDocs Site

Since setting up a full Puppet Server is complex for a small lab, we will use **Puppet Apply**, which allows us to run Puppet in "standalone mode" directly on a VM.

### The Manifest (`deploy_docs.pp`)

```puppet
# Ensure Python and Pip are installed
package { 'python3':
  ensure => installed,
}

package { 'python3-pip':
  ensure => installed,
  require => Package['python3'],
}

# Install MkDocs using a shell command (since pip is often managed via exec in Puppet)
exec { 'install_mkdocs':
  command => '/usr/bin/pip3 install mkdocs',
  create  => true,
  require => Package['python3-pip'],
}

# Create the documentation directory
file { '/home/ubuntu/my-docs':
  ensure => directory,
  owner  => 'ubuntu',
  mode   => '0755',
}

# Initialize MkDocs project
exec { 'init_mkdocs':
  command => '/home/ubuntu/my-docs/mkdocs new .',
  cwd     => '/home/ubuntu/my-docs',
  user    => 'ubuntu',
  creates => '/home/ubuntu/my-docs/mkdocs.yml',
  require => File['/home/ubuntu/my-docs'],
}

# Start MkDocs server on port 8000
exec { 'start_mkdocs':
  command => 'nohup mkdocs serve -a 0.0.0.0:8000 > /dev/null 2>&1 &',
  cwd     => '/home/ubuntu/my-docs',
  user    => 'ubuntu',
  unless  => 'pgrep -f "mkdocs serve"',
  require => Exec['init_mkdocs'],
}
```

### How to Run and Test

#### 1. Provision the VM
Launch a Multipass VM:
```bash
multipass launch --name puppet-vm
```

#### 2. Apply the Manifest
Since Puppet is not installed by default on Ubuntu, we will use a Multipass command to install Puppet and apply the manifest. 

**Copy the manifest to the VM:**
```bash
multipass transfer deploy_docs.pp puppet-vm:/tmp/deploy_docs.pp
```

**Run Puppet Apply:**
```bash
multipass exec puppet-vm -- sudo bash -c "apt-get update && apt-get install -y puppet-agent && /opt/puppetlabs/bin/puppet apply /tmp/deploy_docs.pp"
```

#### 3. Verify the Deployment
**Find the IP:**
```bash
multipass list
```

**Test in Browser:**
Navigate to `http://<VM_IP>:8000`. You should see the MkDocs welcome page.

### Summary of Workflow
| Step | Puppet Concept | Action |
| :--- | :--- | :--- |
| **State Definition** | Manifest (`.pp`) | Describes that packages and files *should* exist. |
| **Discovery** | Facter | Determines the VM's OS and properties. |
| **Application** | Puppet Apply | Compiles the manifest and forces the system to converge to the desired state. |
| **Verification** | HTTP Request | Confirms the service is running on port 8000. |

### Automation with Makefile

To simplify the process of deploying and testing, you can use a `Makefile`. This allows you to trigger the entire workflow with a single command.

Create a file named `Makefile` in your project directory:

```makefile
VM_NAME=puppet-vm
MANIFEST=deploy_docs.pp
PORT=8000

.PHONY: vm test clean

# Provision VM, transfer manifest and apply configuration
vm:
	multipass launch --name $(VM_NAME) || true
	multipass transfer $(MANIFEST) $(VM_NAME):/tmp/$(MANIFEST)
	multipass exec $(VM_NAME) -- sudo bash -c "apt-get update && apt-get install -y puppet-agent && /opt/puppetlabs/bin/puppet apply /tmp/$(MANIFEST)"

# Test if the web service is responding
test:
	@echo "Testing web service at $$(multipass info $(VM_NAME) | grep IPv4 | awk '{print $$2}'):$(PORT)"
	@curl -s http://$$(multipass info $(VM_NAME) | grep IPv4 | awk '{print $$2}'):$(PORT) | grep -q "Welcome" && echo "✅ Test Passed" || echo "❌ Test Failed"

# Cleanup
clean:
	multipass delete $(VM_NAME)
	multipass purge
```

**Usage:**
- Run `make vm` to launch and configure the site.
- Run `make test` to verify the deployment.
- Run `make clean` to remove the VM.
